# Recursion in Mathematics: A Primitive-Based Interpretation

## Title and Domain Context
Recursion in mathematics is typically introduced through inductive definitions, recurrence relations, and proofs by induction. A function or sequence is defined by specifying one or more base values and a rule that reduces a general case to simpler cases. This makes recursion a standard tool for defining objects that are infinite in extent but generated by finite rules, such as sequences, trees, or algebraic structures.

## Primitive Translation Table
| Primitive | Domain-native term | Operational meaning in this domain |
| --- | --- | --- |
| State | Argument or index | The current input value (such as n) or tuple of values needed to apply a recurrence |
| Rule / Update Operator | Recurrence relation | The mapping that produces the next value from prior values |
| Boundary / Constraint | Domain restriction | Conditions on admissible inputs (e.g., n is a nonnegative integer) |
| Base Case / Termination Condition | Initial conditions | Explicit values for the smallest inputs that end the recursion |
| Iteration / Self-Application | Inductive step | Repeated application of the recurrence to smaller inputs |
| Observer / Representation | Expression or notation | The representation used to interpret each step (sequence terms, symbolic forms) |
| Invariant | Inductive invariant | A property preserved across the recurrence (e.g., parity or monotonicity) |

## Law of Recursion (Domain Formulation)
In mathematical terms, a process is a lawful recursion when it has a well-defined input state, a fixed recurrence relation, explicit initial conditions, and a reduction step that moves the input toward those initial conditions under stated domain restrictions. Under a stable representation, such a recursion exhibits predictable progression toward termination and structural self-similarity in intermediate expressions. This claim is structural, not numeric: it specifies when a recursive definition is coherent and when it is not.

## Worked Domain Example
Example: the Euclidean algorithm for the greatest common divisor (gcd).

Primitive mapping in the Euclidean algorithm:
- State: the ordered pair (a, b) of nonnegative integers.
- Rule / Update Operator: if b > 0, update (a, b) to (b, a mod b).
- Boundary / Constraint: a and b must be integers with b >= 0.
- Base Case / Termination Condition: b = 0, at which point the output is a.
- Iteration / Self-Application: repeatedly apply the update rule to the new pair.
- Observer / Representation: the gcd is read off from the state when the base case holds.
- Invariant: gcd(a, b) is preserved under the update rule.

The algorithm is recursive because the rule applies to a smaller instance: the second component strictly decreases until it reaches zero. The invariant explains why the final output is meaningful, and the boundary conditions prevent undefined operations. This example demonstrates that recursion in mathematics is not merely self-reference, but a structured process in which state, rule, boundary, base case, iteration, observer, and invariant align.

## Failure Modes (Domain-Specific)
Recursion fails in mathematics when primitives are broken.

1. Missing base cases. If the initial conditions are not specified, the definition is incomplete, and the recurrence cannot be evaluated. This is a failure of the Base Case primitive.
2. Boundary violations. If the domain restriction is ignored (e.g., applying a recurrence intended for integers to non-integers), the recursion may produce invalid steps. This breaks the Boundary primitive.
3. Observer or representation changes. If the meaning of a term changes mid-definition, the recursion can become ambiguous. For example, switching from integer arithmetic to real arithmetic without explicit rules changes the meaning of the state. This breaks the Observer primitive.

## What This Clarifies (and What It Does Not)
What this primitive framing clarifies:
- Why base cases are not optional in mathematical recursion.
- How recurrence relations can be analyzed through their invariants.
- Why inductive proofs mirror the same primitive structure.
- How domain restrictions prevent undefined or divergent behavior.

What remains outside scope:
- Quantitative convergence rates or closed-form solutions for particular recurrences.
- Non-terminating processes without explicit base cases.
- Whether a given recursion is computationally efficient.

## Relation Back to the Canon
The cross-primitive view confirms that the general canon captures the structure already used in mathematical recursion: explicit base cases, a reduction step, and an invariant-aware observer. It constrains the canon by showing that, in mathematics, the role of the observer is often implicit in notation and must be made explicit when comparing across domains. It does not replace standard mathematical theory, but it makes the structural dependencies of recursion visible and comparable.
